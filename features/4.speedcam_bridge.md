# Feature 4: SpeedCam Bridge (Phase0 Integration)

## Overview
Injects a WindshieldListener into YNavi's navigation stack to capture speed camera
and road event data, then broadcasts it as Android Intents for the Phase0 HUD overlay.

## Architecture
```
DistancesProviderImpl.start()
  -> getWindshield() -> v0 (live Windshield)
  -> Windshield.addListener(this)       [existing YNavi code]
  -> SpeedCamHook.hookWindshield(v0)    [our injection]
    -> SpeedCamBroadcaster.register(windshield)
      -> Proxy.newProxyInstance(WindshieldListener)
      -> Windshield.addListener(proxy)
        -> onRoadEventsChanged()
          -> getRoadEvents() -> List<UpcomingRoadEvent>
            -> broadcast Intent "com.zeekr.phase0.SPEEDCAM_DATA"
```

## Components

### Java (compiled to smali via build_custom_java.sh)
- `custom_java/src/main/java/com/zeekr/phase0bridge/SpeedCamBroadcaster.java`
  - `register(Object windshield)`: takes a live Windshield reference
  - Obtains Context via `ActivityThread.currentApplication()` reflection
  - Creates `java.lang.reflect.Proxy` implementing `WindshieldListener`
  - Only `onRoadEventsChanged()` does work; all other 6 callbacks are no-ops
  - Broadcasts each road event with lat, lon, speedLimit, distance, tags, eventId
  - Action: `com.zeekr.phase0.SPEEDCAM_DATA`
  - Idempotent via AtomicBoolean guard

### Smali Hook
- `custom_java/smali_hook/SpeedCamHook.smali`
  - `hookWindshield(Object)`: static method called from DistancesProviderImpl patch
  - Logs and forwards to `SpeedCamBroadcaster.register()`

### Smali Patch (single injection point)
- `DistancesProviderImpl.start()` at line ~711
  - File: `smali_classes9/.../DistancesProviderImpl.smali`
  - After `Windshield.addListener(this)` where `v0` = live Windshield
  - Insert: `invoke-static {v0}, SpeedCamHook;->hookWindshield(Object;)V`

## Intent Extras (per event)
| Key                | Type   | Description                              |
|--------------------|--------|------------------------------------------|
| lat                | double | Latitude from Event.getLocation()        |
| lon                | double | Longitude from Event.getLocation()       |
| speedLimit         | int    | Speed limit (km/h, rounded from Float)   |
| distance           | double | Distance to finish from RoutePosition    |
| type               | String | Comma-separated EventTag names           |
| tags               | String | Same as type (for compatibility)         |
| eventId            | String | Unique event identifier                  |
| index              | int    | Index within the current batch           |
| count              | int    | Total events in current batch (0=clear)  |
| t_ms               | long   | Timestamp (System.currentTimeMillis)     |
| effectiveSpeedLimit| double | From UpcomingRoadEvent (optional)        |
| speedLimitStatus   | String | SpeedLimitStatus enum name (optional)    |

## Experiment Flags (NOT patched -- not needed)
- `enable_aa_speed_events` (i3.smali field T2): dead experiment, only consumed by reviews class
- `disable_aa_speed_events` (n.smali field l): controls YNavi's internal AA speed event pipeline

Neither flag gates the Windshield road events we hook. The Windshield always receives
road events regardless of these experiment flags.

## Offline Camera Injection (Phase 2)

When YNavi has no network (or the user is in an area not covered by live data),
Phase0's proximity monitor detects a nearby camera from its local Room DB and
pushes it directly into YNavi's projected CarApp next-camera view.

### Mechanism

```
Phase0 SpeedCamProximityMonitor
  -> sendBroadcast "com.zeekr.ynavi.INJECT_CAMERA"
       extras: id (String), distance (String e.g. "350m")
    -> SpeedCamBroadcaster.attachInjectReceiver (dynamic BroadcastReceiver)
         -> injectCamera(id, distance)
              -> reflect xg3.w.sCamera  (live xg3/g instance)
              -> xg3/g.updateCamera(id, distance)
                   -> builds xg3/a0 (SpeedControlCameraAlert)
                   -> pushes into xg3/b->d(xg3/q)  (projected cluster pipeline)
```

### Smali patch — `xg3/w.smali`

`xg3/w` is the Dagger-provided wrapper that holds the live `xg3/g` (NextCameraView)
instance. A static field is added so reflection can reach it without needing a
Dagger injection chain:

```smali
.field public static sCamera:Lxg3/g;
```

Set in the constructor immediately after the instance field assignment:
```smali
# After:  iput-object p1, p0, Lxg3/w;->e:Lxg3/g;
sput-object p1, Lxg3/w;->sCamera:Lxg3/g;
```

File: `src/smali_classes5/xg3/w.smali` lines 23, 47.

### Java — `SpeedCamBroadcaster.attachInjectReceiver()`

Called once from `register()` after `attachListener()`. Dynamically registers
a `BroadcastReceiver` for `com.zeekr.ynavi.INJECT_CAMERA` using
`Context.RECEIVER_EXPORTED` on API 33+ or plain `registerReceiver` below.

### Java — `SpeedCamBroadcaster.injectCamera(id, distance)`

1. Reflects `xg3.w.sCamera` (public static).
2. If non-null: calls `camera.updateCamera(id, distance)` via reflection.
   Logs `SpeedCamBridge: injectCamera: pushed id=<id>` on success.
3. If null (no active CarApp cluster session): creates a synthetic `xg3/g`
   via `getDeclaredConstructor().newInstance()` and calls `updateCamera` on it
   to validate the reflection chain. Logs `injectCamera(synthetic)`.
   This branch fires on the emulator where CarApp handshake fails; on real
   hardware `sCamera` is always populated once navigation guidance starts.

### When `sCamera` is null

`xg3/w` is only instantiated by Dagger when the CarApp cluster session
successfully negotiates a guidance session. This requires:
- A connected CarApp host (real Zeekr cluster or Phase0 host)
- Successful handshake (`performHandshake` returning `SuccessResponse`)
- YNavi's guidance UI initializing (navigation started)

On the emulator: CarApp handshake always fails → `xg3/w` never created → `sCamera` null.
On real hardware with navigation active: `sCamera` is populated.

## Build
The `build_custom_java.sh` script:
1. Compiles Java -> .class files (javac --release 8)
2. Packages into JAR -> DEX via d8 (--min-api 26)
3. Converts DEX -> smali via baksmali
4. Copies hand-written smali hooks from `custom_java/smali_hook/`
5. Merges all smali into `src/smali_classes2/com/zeekr/phase0bridge/`

Called automatically by `build_zeekr.sh` and `build_deepal.sh` before `build_apk.sh`.
