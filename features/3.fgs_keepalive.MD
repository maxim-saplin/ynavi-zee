# Foreground-service keepalive (Android 11 head units)

## What it does

Starts **foreground services** at app launch to keep both the keepalive process and the **main/UI process** alive on devices with aggressive background killing. The keepalive service runs in a dedicated `:persistent` process, while a UI keepalive service runs in the main process so the UI + voice pipeline remain intact in background.

- Services:
  - `ru.yandex.yandexnavi.keepalive.KeepAliveService` (persistent process)
  - `ru.yandex.yandexnavi.keepalive.UiKeepAliveService` (main process)
- Process + FGS type: `android:process=":persistent"`, `foregroundServiceType="location|dataSync"`
- Behavior: posts **ongoing** notifications and returns `START_STICKY`
- Boot + periodic revival:
  - `BootKeepAliveReceiver` starts the service on boot/update.
  - `AlarmManager` reassert loop via `KeepAliveTriggerReceiver` every ~60 seconds.
- Passive location ticks:
  - `LocationManager` (GPS + Network) uses a `PendingIntent` to `KeepAliveTriggerReceiver` to keep the app active even when UI is killed.
- Guidance protection:
  - `GuidanceService` runs in the main process and **requests its own foreground state** via the built-in guidance foreground pipeline to avoid FGS ANR.
- Optional opt-in anchors (user enables in settings):
  - `AnchorNotificationListenerService` (Notification access)
  - `AnchorAccessibilityService` (Accessibility service)

## How to configure (build-time)

This feature is controlled via `features/config.env`:

- `ZEEAPP_KEEPALIVE_ENABLED=1` — enabled (services declared + started)
- `ZEEAPP_KEEPALIVE_ENABLED=0` — disabled (service not declared/started)
- `ZEEAPP_KEEPALIVE_RECEIVER_EXPORTED_DEBUG=1` — optional ADB/manual triggering of `KeepAliveTriggerReceiver` (exported)
- `ZEEAPP_KEEPALIVE_RECEIVER_EXPORTED_DEBUG=0` — default, receiver stays non-exported

Note: Android 8+ requires a notification for foreground services; “keepalive without notification” isn’t supported.

  - `src/smali_classes2/ru/yandex/yandexnavi/keepalive/KeepAliveService.smali`

## How to verify (ADB)

- Confirm service exists (after launching the app):

```bash
adb shell dumpsys activity services | grep -n "ru.yandex.yandexnavi/.keepalive.KeepAliveService"
adb shell dumpsys activity services | grep -n "ru.yandex.yandexnavi/.keepalive.UiKeepAliveService"
adb shell dumpsys activity services | grep -n "com.yandex.navikit_platform.guidance.service.GuidanceService"
```

- Confirm notification/channel:

```bash
adb shell dumpsys notification --noredact | grep -n "channel=keepalive"
```

- Confirm `:persistent` process exists (background):

```bash
adb shell ps -A | grep -n "ru.yandex.yandexnavi:persistent"
```

- Confirm passive location registration (should show `KeepAliveTriggerReceiver` requests):

```bash
# Check active location requests for the app
adb shell dumpsys location | sed -n '/Active Location Requests:/,/^$/p' | grep -n "ru.yandex.yandexnavi" || true
```

- Confirm boot + reassert work (Android 11):

```bash
adb reboot && adb wait-for-device && sleep 20
adb shell dumpsys activity services | grep -n "ru.yandex.yandexnavi/.keepalive.KeepAliveService"

# Force-stop then wait ~2 min to see revival
adb shell am force-stop ru.yandex.yandexnavi
sleep 120
adb shell dumpsys activity services | grep -n "ru.yandex.yandexnavi/.keepalive.KeepAliveService"
```

- Optional: enable anchors

```bash
# Notification access settings
adb shell am start -a android.settings.ACTION_NOTIFICATION_LISTENER_SETTINGS

# Accessibility settings
adb shell am start -a android.settings.ACCESSIBILITY_SETTINGS
```

## Notes & Limitations

- UI process can still be killed by the OS when in background; `UiKeepAliveService` exists to reduce this risk and preserve voice guidance.
- Exact alarms: Android 11 allows `setExactAndAllowWhileIdle()`; `SCHEDULE_EXACT_ALARM` is declared for forward compatibility on Android 12+.
- Guidance service entry: `GuidanceService` is not exported; it is started from inside the app when needed, not via ADB.
- For maximum persistence on vendor ROMs, enabling Notification Access or Accessibility can help maintain a long-lived process.

- Optional: explicitly test both entry paths:

```bash
# Launcher (icon)
adb shell monkey -p ru.yandex.yandexnavi -c android.intent.category.LAUNCHER 1

# Deep-link
adb shell am start -W -n ru.yandex.yandexnavi/ru.yandex.yandexmaps.launch.LaunchActivity -a android.intent.action.VIEW -c android.intent.category.BROWSABLE -d "yandexnavi://keepalive-test"
```
