# App-wide UI scale (density-based)

## What it does

Adds **configurable app-wide UI scaling** that scales **all UI elements together** (including text, layouts, and drawables) using a density-based approach.

- The scaling is applied by overriding the `Configuration.densityDpi` used by the app's `Context`
- This ensures consistent scaling across all UI elements since Android's sizing is largely derived from **dp/sp → px** conversions based on density
- The scale factor is read from a resource file and can be easily adjusted

## Compatibility / hardening notes

Some Android 11 OEM builds (e.g., certain in-car head units) can crash when:

- A `Configuration` used for `applyOverrideConfiguration(...)` has `densityDpi <= 0` (undefined), and code blindly scales it.
- `applyOverrideConfiguration(...)` throws `IllegalStateException` on some devices (AppCompat itself treats this as a guarded operation).

To harden behavior, the scaling implementation is defensive:

- `densityDpi` fallback: if the incoming `Configuration.densityDpi <= 0`, use `Resources.getDisplayMetrics().densityDpi` as the **base**, then apply the scale factor (multiply + clamp).
- Clamping: scaled density is clamped to a reasonable range (currently **120..960**) to avoid extreme/invalid values.
- Fail-safe: scaling wrappers catch failures and fall back to the original `Context` / `Configuration`.
- `MapActivity` guards its `applyOverrideConfiguration(...)` call with a try/catch for `IllegalStateException`.

Real-world result: **hardened builds worked** at both `100%` and `150%` scale on the affected Android 11 head unit.

## How to change the scale factor

Edit the scale factor in:

- `src/res/values/zeeapp_scaling.xml`

Resource:

- `zeeapp_ui_scale` (fraction, percentage)

Examples:

- Disable scaling (baseline): `100%`
- 1.5x scaling (everything 1.5x larger): `150%`
- 0.75x scaling (everything 0.75x smaller): `75%`

## Code changes (where and what)

### Scale resource

File:

- `src/res/values/zeeapp_scaling.xml`

Content:

- Defines `<fraction name="zeeapp_ui_scale">…%</fraction>` (percentage; `100%` = no scaling).

### Helper class

File:

- `src/smali_classes2/ru/yandex/yandexnavi/zee/ZeeUiScale.smali`

Methods:

- `wrapBaseContext(Context): Context` - Wraps a context with scaled density configuration (defensive: fallback/clamp/try-catch)
- `applyToConfiguration(Context, Configuration): Configuration` - Applies scaling to a `Configuration` object used for override configurations (defensive: supports configs with `densityDpi <= 0`)

### AppCompat base (Activities)

File:

- `src/smali/androidx/appcompat/app/s.smali`

Change summary:

- In `attachBaseContext(Context)`, after AppCompat's delegate wraps the context, apply scaling:
  - `p1 = ZeeUiScale.wrapBaseContext(p1)`
- This covers the bulk of UI screens that inherit from AppCompat

### Application base context

File:

- `src/smali_classes2/ru/yandex/yandexmaps/app/p2.smali`

Change summary:

- In `attachBaseContext(Context)`, after existing language logic finalizes `p1`, apply scaling:
  - `p1 = ZeeUiScale.wrapBaseContext(p1)`
- This ensures app-level resource access during startup sees the scaled density

### MapActivity locale override

File:

- `src/smali_classes2/ru/yandex/yandexmaps/app/MapActivity.smali`

Change summary:

- `MapActivity` applies an in-app language override via `applyOverrideConfiguration(languageConfig)`.
- To preserve UI scaling when that locale override is applied:
  - `languageConfig = ZeeUiScale.applyToConfiguration(baseContext, languageConfig)`
- Important ordering: `applyOverrideConfiguration(...)` must run **before** `super.attachBaseContext(...)` (otherwise Android may throw/ignore the override).
- Hardening: wrap the `applyOverrideConfiguration(...)` call in try/catch (`IllegalStateException`) to avoid OEM-specific crashes.
