# Traffic Recovery Host Reset

This repo now carries the accepted fix for the traffic layer staying stale
after connectivity returns. The earlier Phase0 logic that waited for validated
internet and restarted YNavi was a temporary workaround. The source of truth is
now the YNavi-side smali patch documented here.

## Scope

- recover traffic after network restoration without requiring an external app restart
- keep the recovery logic inside YNavi rather than depending on Phase0 boot or watchdog policy
- preserve the rest of the navigation session while forcing the traffic stack to reinitialize

## Implementation

### `src/smali_classes5/au2/t0.smali`

- exposes `ru.yandex.yandexmaps.overlays.api.m.getActivity()` through the Dagger provider used by the traffic overlay path
- gives the recovery code access to the current host `Activity`

### `src/smali_classes5/ru/yandex/yandexmaps/overlays/internal/traffic/b.smali`

- increments the internal recovery counter when traffic recovery fails
- on the first failed recovery tick, schedules a delayed retry after `0x3a98` milliseconds (`15000` ms)
- on the second failed recovery tick, removes the stale traffic listener, hides the old traffic layer, resolves the host `Activity`, and calls `Activity.recreate()` when that activity is not already finishing

In practice this replaces the old "wait for internet, then restart YNavi from
Phase0" approach with an in-app reset of the map host.

## Out Of Scope

- Phase0 boot-time network gating
- Phase0 automatic YNavi restart policy
- the hosted CarApp / HUD rebind strategy tracked in `MINIMAP.md`
- the independent `ForegroundServiceStartNotAllowedException` hosted-start issue

## Validation

The accepted branch was validated in the workspace-level investigation and is
the branch to keep:

- EV5 standalone route-active recovery passed
- EV6 hosted HUD recovery passed
- authoritative report: `../docs/37_6_YNAVI_TRAFFIC_RECOVERY_PATCH_VALIDATION_REPORT.md`

The delayed second-tick host reset was accepted because it recovered traffic
without the behavioral regressions seen in the rejected alternatives.

## Rejected Directions

- forcing the reset immediately on the first failed tick
- traffic-layer-only refresh branches that did not reliably recover MapKit state
- keeping Phase0 automatic restart as the product fix

## Maintenance Note

If future traffic regressions appear, start by diffing these two smali files
before changing any Phase0 watchdog behavior. Phase0 cleanup should remove the
legacy workaround, not replace this in-repo fix.
